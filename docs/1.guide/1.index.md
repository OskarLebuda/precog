# Getting started

> A Nuxt module that asks [TypeSafe](https://typesafe.ai/) Jev which link a visitor is about to
> click, then warms exactly that navigation.

`NuxtLink` already prefetches every link that enters the viewport, and Chrome already guesses
on hover. This module tries to prefetch three links instead of thirty, and to start before the
hover.

## Install

:pm-x{command="nuxt module add nuxt-precog"}

Set a key from [console.typesafe.ai](https://console.typesafe.ai/settings/keys):

```sh [.env]
NUXT_PRECOG_API_KEY="your-api-key"
```

That is the whole setup. The defaults prefetch at most three links and never prerender.

Run `nuxt dev`, open a page and press <kbd>Shift</kbd>+<kbd>P</kbd> to see what it is doing.
The overlay is development only unless you ask for it with `overlay: true`.

## Let it prerender as well

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ["nuxt-precog"],
  precog: {
    mode: "auto",
    takeOverNuxtLinkPrefetch: true,
  },
});
```

::warning
A prerendered page runs its JavaScript: analytics fire, `onMounted` fetches run, media can
autoplay. Read [prerendering has side effects](/guide/how-it-works#prerendering-has-side-effects)
before turning this on.
::

## What it costs

Predictions are not free. The benchmark measures about 15 Jev calls per session, of which the
server answers roughly a fifth from its own cache. Before pointing this at real traffic, tune
`minIntervalMs`, `cache.ttlSeconds` and the budgets.

## Is it worth it for you?

Honestly, sometimes not.

- If your visitors hover a link for a while before clicking, Chrome's own document rules at
  `eagerness: moderate` already cover you, for free and with no model. See
  [benchmarks](/guide/benchmarks).
- The in-app win comes from warming payloads, which only exist for prerendered routes with
  `experimental.payloadExtraction`.
- It improves the median navigation and does nothing for the tail.
